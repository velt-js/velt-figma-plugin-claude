# velt-customize — operating brief

Turning a Figma design into clean Velt UI customization (comments + notifications, React) via Planner → Builder → Judge.

## The one rule that governs everything
**`guide/` is the first source of truth — but its *silence* is not a verdict.** For any decision — which component, layer, identifier, behavior, data field, how to verify, how to handle a blocker — READ the relevant `guide/` file and apply it. Knowledge lives across: identifiers (`reference/*`), **prop behavior & interactions** (`reference/behaviors.md`), **data fields / events / custom-data** (`reference/data-models.md`), and **what a component is *for*** (`reference/component-definitions.md`). When the guide doesn't cover something or you're unsure, **don't guess, don't hedge, don't declare it impossible** — **verify against ground truth**: Velt Docs MCP / official Velt docs → the live SDK's behavior/types → an empirical test in the running app; then state the verified fact (and ideally feed it back into the guide). Never invent a name (R10); never hack (R0).

## Flow (do not skip preflight or the gate)
0. **Preflight (before anything) — fail fast, fail clear, NO fallback.** Check + print a ✓/⚠/✗ readiness summary with a plain-language fix per item: guide present · **Figma MCP reachable + node resolves (Dev Mode)** · **Velt installed in the repo** · **app runs + Velt renders** (capture the default-UI baseline) · **`claude-in-chrome` (Chrome MCP) connected** · **auth** (never enter creds — manual login → pause and ask) · **`/loop` availability** (optional — cadence only; the orchestrator owns the block loop in `owned-loop` and termination is always `verdict-gate-blocks.mjs`'s exit code, never `/goal`). **Hard items — must pass, no fallback: guide · Figma MCP · Velt-installed · app+Velt renders · Chrome MCP.** If Figma MCP is down → HALT (do **not** read the design via Chrome screenshots — that fallback degraded a prior run); if Chrome MCP is down → HALT before building. Any ✗ **HALTS with the fix and changes nothing**; translate tool errors into plain language, never dump a raw stack. Only auth/live-app + `/loop` are **deferred/soft** (auth enforced at the gate; manual-login pause is the one safety exception). Idempotent — fix and re-run.
1. **Plan (read-only) — extract → map. The Planner is the BRAIN; go DEEP** (see [`build-methodology.md`](../../guide/build-methodology.md)). Via **Figma MCP**: go through **every frame**, list **all surfaces** (sidebar AND pin dialog — don't miss one), every element, **every state** (collapsed-default, focused, expanded, hover, selected, resolved, empty, autocomplete, filter-open, options, toast/tooltip). Then **EXTRACT the `designSpec` deterministically** (`scripts/figma-extract.mjs`, [`extraction.md`](../../guide/extraction.md)) — exact spacing/sizing/radius/typography/colours + the **exported icon SVGs** (R17); numbers are read, never eyeballed. **Read the host's existing Velt props** as design intent. Recognize via `component-definitions.md`; confirm behavior via `behaviors.md`, data via `data-models.md`. Pick the layer via `02-decision-tree.md` (Q1–Q4 + S1–S8). Then **MAP** (Velt Code Connect, [`reference/manifest.md`](../../guide/reference/manifest.md)): per element → `{slot, slotType, fillWith, hostProps, cssDecls}` — **props-first** (structure a prop produces is never CSS, R21) and **supply every `mustSupply` slot** (R19). **List what's NOT supported by default** with the plan for each (prop/wireframe · primitives/headless *only if the data model supports it* · event-driven toast/tooltip · genuine gap → closest alternative · hacky → confirm). Output a **complete, decided Connect Map + designSpec**, each decision tagged `verified/assumed/unknown→verify`. **Then ENUMERATE BLOCKS** (`scripts/enumerate-blocks.mjs` → `blocks.json`): every Figma frame/state-variant is one **block** — the completeness oracle. The design's frames ARE the checklist (every drawn state must be built + matched, nothing in the design may be missing); annotate each block's `state`/`drive`/`fixture`/`liveSelector` (how the Judge reaches + seeds that state). The block list is the per-surface coverage the gate presents.
2. **Coverage gate — the ONE user input.** Present the matrix + recommendation and ask **only** which approach to implement. After this, do **not** stop for the user again.
3. **Build → Judge loop — BLOCK BY BLOCK, one Figma block perfected before the next; HARNESS-OWNED, terminated MECHANICALLY by `verdict-gate-blocks.mjs` exit code** (see [`build-methodology.md`](../../guide/build-methodology.md) Step 2; read [`build-gotchas.md`](../../guide/build-gotchas.md)). The orchestrator owns a **block queue** from `blocks.json` and advances one block per `step`; it does NOT rely on `/goal` (an LLM opinion over the transcript that let prior runs stop early) — the stop condition is the gate's exit code over persisted artifacts. `/loop` may provide cadence but is never the fidelity gate. **A block is iterated until it PASSes (visual ∧ layout ∧ contract ∧ stability — no interactive target shifts mid-interaction, R27); only then advance.** Per block:
   - **Builder** (maker): one surface at a time (dialog first). **Execute the Connect Map verbatim** — set host props first (R21), **supply every `mustSupply` slot** with the design's exported SVG/text (R19; never a Velt default), build the structure, then apply the map's **exact `cssDecls`** to the real Velt classes (`!important`, R9b) — **don't re-measure or eyeball**. Generate an `icons/` file from the exported SVGs. Prefer the native slot + CSS before a custom variant (P4/R12). Then interactivity/states, then test features functionally, then the next surface, then the unsupported items. Files under `ui-customization/` only (R11/R18); one stylesheet (R8); one `<VeltWireframe>` (R1). Manifest-driven smoke-test before handoff (every `mustSupply` slot supplied; gross-undershoot guard).
   - **Judge** (checker, fresh context — never the maker): for the **current block**, (1) **SEED + DRIVE the block's state IN-APP** (run `block.drive`/`fixture` inside the live app session — pierce the shadow-DOM composer, type into `.hw-rail-inner [contenteditable]`, click the **visible** send button by coordinate, hover/open as the state needs; wait for `block.drive.assert` before measuring — never capture a half-loaded or wrong state); (2) **CAPTURE device-res** (`scripts/capture-block.mjs` → 708px PNG @DPR2; NOT the Chrome MCP JPEG); (3) **VISUAL DIFF** the capture vs the block's frame with `scripts/visual-diff.mjs --mask-text-from <designSpec>` — chrome-only (text is masked; the 354px width-match aligns chrome to ~0%), and **any region with `fill ≥ ~0.05` is a real structural diff ⇒ FAIL** (thin 1px-drift outlines are delta-compare's job, not this); (4) **DELTA-COMPARE** for exact numbers — `scripts/delta-compare.mjs` `BROWSER_PROBE` `{surfaceSelector, tol, elements, relations, gaps}`: live `getComputedStyle` (**style:** ΔE<2, ±1px) AND `getBoundingClientRect` (**layout:** box ±2-3px, gaps, relations, missing/extra). delta-compare owns text/colour/size/position (font-render-immune); visual-diff owns missing/extra/wrong-element structure. For each painted node run **`LAYER_PROBE`** — FAIL on `ownerMismatch` (R23) or any `neutralize[]` (R22). Run **`CONTRACT_PROBE`** on the post-reconciliation DOM (R25) — FAIL on any `MISSING`/`CONTAINMENT`/`CARDINALITY`/`PHANTOM_INTERACTIVE` (a boolean veto regardless of pixels). **No aggregate score; any significant visual region / style / layout / reconciliation / contract violation ⇒ FAIL** with the localized regions + delta rows as feedback. PASS = **visual ∧ layout ∧ contract**. **Hard gates:** console error / unbuilt / `width===0` ⇒ `BLOCKED`/`FAIL`; every `mustSupply` slot present + carrying the design's SVG/content (R17/R19); no feature the design lacks (R24). A non-render → **app-vs-build triage first** (`BLOCKED`, not `FAIL`, when env/auth is the blocker). **The Judge writes its per-block disposition into `block-report.json` and SURFACES the evidence; it NEVER declares the run done — `verdict-gate-blocks.mjs` does, by exit code.**
   - **Termination = the MECHANICAL `verdict-gate-blocks.mjs` exit code over `blocks.json`, never an agent's say-so.** The completeness oracle is the Figma-derived `blocks.json` (every frame/state). Each block the Judge writes its disposition (built · driven · `visualDiff` · `deltaCompare` · reconciliation · contract) into **`block-report.json`**; the orchestrator runs `verdict-gate-blocks.mjs --blocks blocks.json --report block-report.json`. **A run that built fewer blocks than `blocks.json`, didn't drive a block's state, or has no visual-diff artifact for a block is `INCOMPLETE` (exit 3) — NOT pass, so the loop CANNOT terminate** (the structural fix for M5: building 5 of 16 frames = INCOMPLETE). PASS = exit 0 (every block built + driven + clean). A measured-but-wrong block ⇒ FAIL (exit 2). This is a script exit code, not `/goal`'s judgment.
   - **Keep iterating the current block** until its visual-diff has no significant region AND its delta tables are empty, then advance. A retry is accepted only if the **significant-region count / failing-diff count strictly drops** (forced improvement); stuck-detection aborts a no-progress chain. **Never declare a gap to escape** — exhaust inspect→override→data-driven→full-container first.
4. **Report (only at the very end) — polished + honest.** A clean human-readable summary from `templates/`: per surface **what was done · what's pending · where blocked**, logged assumptions, *verified* gaps, the **required host changes** the user must apply (R18 — tested, reverted, listed), screenshots, code.

## Hard guardrails
- Verify each surface before the next (R15/R16). A goal is never "met" without evidence.
- Never enter credentials; use the app's existing auth/test harness — if manual login is needed, pause and ask.
- Touch only `components/velt/ui-customization/` + the report dir. **Never change the host app's non-Velt UI or default behavior (R18)** — a required host change is applied temporarily, verified, **reverted**, and reported to the user as a manual step, never baked in. No deletes, no config/build changes, no commits unless asked.
- **Exactly ONE blocking user question for the whole run: the approach at the coverage gate.** Recognition ambiguities, retries, escalations → autonomous; log + surface only in the final report. (A hard preflight failure halts with a fix; manual-auth pause is a safety exception.)
- A goal is `met` only on a genuine side-by-side match — never on "structure present" or "looks close". Loop until it truly matches.
- Never declare an SDK gap to escape the loop — exhaust inspect (to the leaf element) → CSS vars + class `!important` → data-driven (user color/config) → full-container wireframe, with evidence, first.

## Verified facts (don't relitigate — full detail in the guide)
One `<VeltWireframe>` per app · container slots drop undeclared children → declare the full tree · `ThreadCard` MUST nest in `Body → Threads` · root wireframe auto-removes shadow, nested-only needs `shadowDom={false}` · CSS variables cross shadow, class CSS doesn't · pin index/number slots are empty → fill via `velt-data` · use `VeltCommentDialog`, never the deprecated `VeltCommentThread`.

## When unsure
Read the guide file. If the guide is silent, **verify against ground truth** (Velt Docs MCP / official docs → live SDK → running app) — don't guess or hedge. Only a capability that is genuinely absent *after that verification* (e.g. a field the data model doesn't store) is an SDK gap (`guide/sdk-gaps-and-blockers.md`) — never a hack, and never a guess.
