# velt-customize — operating brief

Turning a Figma design into clean Velt UI customization (comments + notifications, React) via Planner → Builder → Judge.

## The one rule that governs everything
**`guide/` is the first source of truth — but its *silence* is not a verdict.** For any decision — which component, layer, identifier, behavior, data field, how to verify, how to handle a blocker — READ the relevant `guide/` file and apply it. Knowledge lives across: identifiers (`reference/*`), **prop behavior & interactions** (`reference/behaviors.md`), **data fields / events / custom-data** (`reference/data-models.md`), and **what a component is *for*** (`reference/component-definitions.md`). When the guide doesn't cover something or you're unsure, **don't guess, don't hedge, don't declare it impossible** — **verify against ground truth**: Velt Docs MCP / official Velt docs → the live SDK's behavior/types → an empirical test in the running app; then state the verified fact (and ideally feed it back into the guide). Never invent a name (R10); never hack (R0).

## Flow (do not skip preflight or the gate)
0. **Preflight (before anything) — fail fast, fail clear, NO fallback.** Check + print a ✓/⚠/✗ readiness summary with a plain-language fix per item: guide bundled · **Figma MCP reachable + node resolves (Dev Mode)** · **Velt installed in the repo** · **app runs + Velt renders** (capture the default-UI baseline) · **`claude-in-chrome` (Chrome MCP) connected** · **auth** (never enter creds — manual login → pause and ask) · **`/loop` + `/goal` availability** (Claude Code version + hooks/trust — soft: the main session drives the loop via native `/loop` and terminates via native `/goal`; if either is absent, the orchestrator runs `owned-loop` and still uses the fresh-context Judge as the separate verifier). **Hard items — must pass, no fallback: guide · Figma MCP · Velt-installed · app+Velt renders · Chrome MCP.** If Figma MCP is down → HALT (do **not** read the design via Chrome screenshots — that fallback degraded a prior run); if Chrome MCP is down → HALT before building. Any ✗ **HALTS with the fix and changes nothing**; translate tool errors into plain language, never dump a raw stack. Only auth/live-app + `/loop`+`/goal` are **deferred/soft** (auth enforced at the gate; manual-login pause is the one safety exception). Idempotent — fix and re-run.
1. **Plan (read-only) — extract → map. The Planner is the BRAIN; go DEEP** (see [`build-methodology.md`](../../guide/build-methodology.md)). Via **Figma MCP**: go through **every frame**, list **all surfaces** (sidebar AND pin dialog — don't miss one), every element, **every state** (collapsed-default, focused, expanded, hover, selected, resolved, empty, autocomplete, filter-open, options, toast/tooltip). Then **EXTRACT the `designSpec` deterministically** (`scripts/figma-extract.mjs`, [`extraction.md`](../../guide/extraction.md)) — exact spacing/sizing/radius/typography/colours + the **exported icon SVGs** (R17); numbers are read, never eyeballed. **Read the host's existing Velt props** as design intent. Recognize via `component-definitions.md`; confirm behavior via `behaviors.md`, data via `data-models.md`. Pick the layer via `02-decision-tree.md` (Q1–Q4 + S1–S8). Then **MAP** (Velt Code Connect, [`reference/manifest.md`](../../guide/reference/manifest.md)): per element → `{slot, slotType, fillWith, hostProps, cssDecls}` — **props-first** (structure a prop produces is never CSS, R21) and **supply every `mustSupply` slot** (R19). **List what's NOT supported by default** with the plan for each (prop/wireframe · primitives/headless *only if the data model supports it* · event-driven toast/tooltip · genuine gap → closest alternative · hacky → confirm). Output a **complete, decided Connect Map + designSpec**, each decision tagged `verified/assumed/unknown→verify`.
2. **Coverage gate — the ONE user input.** Present the matrix + recommendation and ask **only** which approach to implement. After this, do **not** stop for the user again.
3. **Build → Judge loop — driven by native `/loop`, terminated by native `/goal`; Step-2 methodology, in SMALL PATCHES, AUTONOMOUS to a TRUE match** (see [`build-methodology.md`](../../guide/build-methodology.md) Step 2; read [`build-gotchas.md`](../../guide/build-gotchas.md)). The main-session command owns the loop (only it can type slash commands): after the gate it sets `/goal` (the terminator) + `/loop` (the cadence), and **each `/loop` turn advances exactly one patch** by invoking `velt-orchestrator` in `step` mode — whose final message surfaces the Judge's evidence into the transcript for `/goal`. (If `/loop`/`/goal` are unavailable, the orchestrator runs in `owned-loop` fallback.) Per patch:
   - **Builder** (maker): one surface at a time (dialog first). **Execute the Connect Map verbatim** — set host props first (R21), **supply every `mustSupply` slot** with the design's exported SVG/text (R19; never a Velt default), build the structure, then apply the map's **exact `cssDecls`** to the real Velt classes (`!important`, R9b) — **don't re-measure or eyeball**. Generate an `icons/` file from the exported SVGs. Prefer the native slot + CSS before a custom variant (P4/R12). Then interactivity/states, then test features functionally, then the next surface, then the unsupported items. Files under `ui-customization/` only (R11/R18); one stylesheet (R8); one `<VeltWireframe>` (R1). Manifest-driven smoke-test before handoff (every `mustSupply` slot supplied; gross-undershoot guard).
   - **Judge** (checker, fresh context — never the maker): after **each patch**, **MEASURE THE WHOLE SURFACE** — auto-derive the checklist from the FULL Connect Map / `designSpec` (every mapped element + every `mustSupply` slot, no hand-picking), then inject the delta probe (`scripts/delta-compare.mjs` `BROWSER_PROBE`, object form `{surfaceSelector, tol, elements, relations, gaps}`) to diff live `getComputedStyle` against the spec (**style:** ΔE<2, ±1px, keywords exact) AND surface-relative `getBoundingClientRect` (**layout:** box ±2-3px, sibling gaps, relations name-left-of-time/message-below-header/actions-top-right, missing/extra elements). Run a cheap **gross-mismatch pre-check first** (total height / element count / extents). For each painted node run **`LAYER_PROBE`** (layer reconciliation) — FAIL on `ownerMismatch` (wrong layer styled, general R23) or any `neutralize[]` (a co-box wrapper still paints padding/bg/border, general R22). Run **`CONTRACT_PROBE`** on the post-reconciliation DOM (the mount-map functional veto, R25) — FAIL on any `MISSING`/`CONTAINMENT`/`CARDINALITY`/`PHANTOM_INTERACTIVE` violation, a **boolean veto that FAILs regardless of pixels** (a pixel-perfect-but-behaviorally-dead surface). Then a **mandatory visual side-by-side** (full surface vs Figma frame) and **name every difference — any nameable diff ⇒ FAIL**. **No aggregate score; any style/layout/reconciliation/contract violation or nameable visual diff ⇒ FAIL** with the named diffs as feedback. PASS = **visual ∧ layout ∧ contract**. **Hard gates:** console error / unbuilt / `width===0` ⇒ `BLOCKED`/`FAIL`; every `mustSupply` slot present + carrying the design's SVG/content (R17/R19); no feature the design lacks (R24). Drive **every state** (incl. hover-reveal). A non-render → **app-vs-build triage first** (`BLOCKED`, not `FAIL`, when env/auth is the blocker). **The Judge SURFACES its full evidence into the transcript (gross check + style + layout tables + named visual diffs + verdict) and NEVER declares the run done.**
   - **Termination = the MECHANICAL `verdict-gate`, never an agent's say-so.** After extraction, the checklist is GENERATED (`build-checklist.mjs → checklist.json`: every distinct styled appearance + every mustSupply + every contract part + every state). Each loop the Judge emits **`judge-report.json`** (a disposition for every checklist element + the per-state `visualSideBySide` artifact + reconciliation + contract) and runs **`verdict-gate.mjs`**. **A report that samples (covers fewer elements than the checklist), skips a state, or omits the visual artifact is `INCOMPLETE` — which is NOT pass, so the loop CANNOT terminate** (this is the structural fix for the M5/E2E sample-and-pass: a Judge measuring 5 of 93 appearances is 5% coverage = INCOMPLETE). `/loop` provides the cadence in the main session; `/goal` terminates only on a surfaced **verdict-gate PASS** (100% coverage + all clean). `/loop`'s native "Claude decides done" is NEVER the gate. If `/loop`/`/goal` are unavailable, the orchestrator runs `owned-loop` and still runs `verdict-gate` as the terminator.
   - **Keep iterating** (across `/loop` turns, or within `owned-loop`) until the style + layout deltas are empty and the visual side-by-side is clean across all states. A retry is accepted only if the **failing-diff count strictly drops** (forced improvement); stuck-detection aborts a no-progress chain. **Never declare a gap to escape** — exhaust inspect→override→data-driven→full-container first.
4. **Report (only at the very end) — polished + honest.** A clean human-readable summary from `templates/`: per surface **what was done · what's pending · where blocked**, logged assumptions, *verified* gaps, the **required host changes** the user must apply (R18 — tested, reverted, listed), screenshots, code.

## Hard guardrails
- Verify each surface before the next (R15/R16). A goal is never "met" without evidence.
- Never enter credentials; use the app's existing auth/test harness — if manual login is needed, pause and ask.
- Touch only `components/velt/ui-customization/` + the report dir. **Never change the host app's non-Velt UI or default behavior (R18)** — a required host change is applied temporarily, verified, **reverted**, and reported to the user as a manual step, never baked in. No deletes, no config/build changes, no commits unless asked.
- **Exactly ONE blocking user question for the whole run: the approach at the coverage gate.** Recognition ambiguities, retries, escalations → autonomous; log + surface only in the final report. (A hard preflight failure halts with a fix; manual-auth pause is a safety exception.)
- A goal is `met` only on a genuine side-by-side match — never on "structure present" or "looks close". Loop until it truly matches.
- Never declare an SDK gap to escape the loop — exhaust inspect (to the leaf element) → CSS vars + class `!important` → data-driven (user color/config) → full-container wireframe, with evidence, first.

## Verified facts (don't relitigate — full detail in the guide)
One `<VeltWireframe>` per app · container slots drop undeclared children → declare the full tree · `ThreadCard` MUST nest in `Body → Threads` · root wireframe auto-removes shadow, nested-only needs `shadowDom={false}` · CSS variables cross shadow, class CSS doesn't · pin index/number slots are empty → fill via `velt-data` · use `VeltCommentDialog`, never the deprecated `VeltCommentThread`.

## When unsure
Read the guide file. If the guide is silent, **verify against ground truth** (Velt Docs MCP / official docs → live SDK → running app) — don't guess or hedge. Only a capability that is genuinely absent *after that verification* (e.g. a field the data model doesn't store) is an SDK gap (`guide/sdk-gaps-and-blockers.md`) — never a hack, and never a guess.
